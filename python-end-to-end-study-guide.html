Answer: A dict lookup can miss. Saying so in the hint forces you (and your editor) to handle the None case, preventing a crash like None.upper().

1.4 Exceptions — handling errors cleanly

try:
    number = int("abc")
except ValueError:
    print("That is not a number")

# Full structure: try / except / else / finally
def read_number(text: str) -> int | None:
    try:
        value = int(text)
    except ValueError as err:
        print("Bad input:", err)
        return None
    else:
        # runs only if NO error happened
        return value
    finally:
        # ALWAYS runs (good for cleanup)
        print("done checking")
# Custom exceptions
class AppError(Exception):
    """Base error for my app."""

class PaymentError(AppError):
    def __init__(self, order_id: int, reason: str):
        super().__init__(f"Order {order_id} failed: {reason}")
        self.order_id = order_id

try:
    raise PaymentError(42, "card declined")
except AppError as err:           # catches PaymentError too
    print(err)

# Chaining errors — keeps the original traceback
try:
    int("x")
except ValueError as err:
    raise RuntimeError("Could not load config") from err

1.5 Iterators and generators — lazy, memory‑friendly loops

# What an iterator does under the hood
nums = [10, 20, 30]
it = iter(nums)
print(next(it))          # 10
print(next(it))          # 20
print(next(it))          # 30
# next(it) now raises StopIteration

# A generator: function with yield
def countdown(start: int):
    while start > 0:
        yield start
        start -= 1

for n in countdown(3):
    print(n)             # 3, 2, 1

# Low-memory file reading
def read_big_file(path: str):
    with open(path) as f:
        for line in f:
            yield line.strip()      # one line at a time

# Generator expression (lazy, no big list)
total = sum(n * n for n in range(1_000_000))
Remember: A generator can be used only once. After it finishes, it is empty.

1.6 Context managers — setup and guaranteed cleanup

# Classic: file handling
with open("notes.txt", "w") as f:
    f.write("hello")
# file is closed automatically, even if write() failed

# Custom context manager via decorator
from contextlib import contextmanager

@contextmanager
def opened_connection(name: str):
    print(f"connecting to {name}")
    conn = {"name": name}
    try:
        yield conn
    finally:
        print(f"closing {name}")

with opened_connection("db") as c:
    print("using", c)
Remember: Use with for anything that must be closed or released: files, network connections, locks, database transactions.

Part 2 — Asyncio and concurrency

2.1 The big idea — waiting vs. working

Most slow programs are not busy thinking — they are waiting (for a web server, a database, a file). While waiting, the CPU does nothing. Think of a cook making tea and toast:

  • Blocking cook: boils water, stares until it boils, then makes toast.
  • Async cook: starts the water, puts bread in the toaster, handles whichever is ready first.
🔑 Three words to keep straight
WordMeaningPython tool
ConcurrencyMany tasks in progress, taking turnsasyncio, threads
ParallelismMany tasks running at the exact same instant on different CPU coresmultiprocessing
AsyncConcurrency where tasks politely pause while waitingasyncio
🧰 Which tool for which job?
Your task is mostly…Best choice
Waiting on network or disk (I/O-bound), many things at onceasyncio
Waiting, but the library is not asyncthreads (asyncio.to_thread)
Heavy math or CPU workmultiprocessing
Remember: asyncio speeds up waiting, not calculating. It runs on one thread.

2.2 async and await basics

import asyncio

async def say_hello():
    print("Hello")
    await asyncio.sleep(1)      # pause here, let others run
    print("World")

asyncio.run(say_hello())
📌 Three things to learn
  1. async def creates a coroutine function. Calling it does not run it — it returns a coroutine object.
  2. await means “pause me until this finishes, and let other tasks run meanwhile.” Only valid inside async def.
  3. asyncio.run(...) starts the event loop and runs your main coroutine. Call it once, at the top level.

Sequential vs concurrent — see the difference

# Sequential (slow): ~3 seconds
import asyncio, time

async def fetch(name: str, delay: float) -> str:
    await asyncio.sleep(delay)          # pretend network call
    return f"{name} done"

async def main():
    start = time.perf_counter()
    a = await fetch("A", 1)
    b = await fetch("B", 1)
    c = await fetch("C", 1)
    print(a, b, c)
    print(f"{time.perf_counter() - start:.1f}s")   # ~3.0s

asyncio.run(main())
# Concurrent (fast): ~1 second
async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        fetch("A", 1),
        fetch("B", 1),
        fetch("C", 1),
    )
    print(results)                                  # ['A done', 'B done', 'C done']
    print(f"{time.perf_counter() - start:.1f}s")   # ~1.0s

asyncio.run(main())
⚠️ Common beginner mistake: forgetting await.
async def main():
    fetch("A", 1)        # WRONG: forgot await, nothing runs
    await fetch("A", 1)  # RIGHT
Python warns you: coroutine was never awaited.

2.3 Running many tasks

# asyncio.gather — run together, results in order
results = await asyncio.gather(fetch("A", 1), fetch("B", 2))

# Collect errors instead of raising
results = await asyncio.gather(
    fetch("A", 1),
    might_fail(),
    return_exceptions=True,       # errors come back as list items
)
for r in results:
    if isinstance(r, Exception):
        print("failed:", r)
# create_task — start now, await later
async def main():
    task1 = asyncio.create_task(fetch("A", 2))
    task2 = asyncio.create_task(fetch("B", 1))

    print("both started, doing other work...")
    await asyncio.sleep(0.5)

    print(await task1)
    print(await task2)

asyncio.run(main())
Important: keep a reference to your tasks (like the variables above). If you throw the reference away, Python may delete the task before it finishes. 
# TaskGroup (Python 3.11+) — the safest way
async def main():
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(fetch("A", 1))
        t2 = tg.create_task(fetch("B", 2))
    # we reach here only when ALL tasks are done
    print(t1.result(), t2.result())

asyncio.run(main())
# Timeouts (Python 3.11+)
async def slow():
    await asyncio.sleep(10)

async def main():
    try:
        async with asyncio.timeout(2):
            await slow()
    except TimeoutError:
        print("too slow!")

# Older Python: await asyncio.wait_for(slow(), timeout=2)
# Limit concurrency with Semaphore
sem = asyncio.Semaphore(5)          # only 5 at a time

async def limited_fetch(i: int) -> int:
    async with sem:
        await asyncio.sleep(1)      # pretend request
        return i

async def main():
    results = await asyncio.gather(*(limited_fetch(i) for i in range(20)))
    print(len(results))             # 20, in about 4 seconds, not 20

asyncio.run(main())
# Queue — producers and consumers
async def producer(q: asyncio.Queue):
    for i in range(5):
        await q.put(i)
    await q.put(None)               # signal: no more work

async def consumer(q: asyncio.Queue):
    while True:
        item = await q.get()
        if item is None:
            break
        print("processing", item)

async def main():
    q: asyncio.Queue = asyncio.Queue()
    await asyncio.gather(producer(q), consumer(q))

asyncio.run(main())
🧠 Interview / thinking question: “You need to call 100 external APIs. How do you avoid overwhelming them while still being fast?”
Answer outline: Use httpx.AsyncClient with asyncio.gather, wrap each call in an asyncio.Semaphore(5…10) to cap concurrency, set per‑request timeouts, and use retries with exponential backoff. Never start 1000 requests without a limit.

2.4 Blocking code — the biggest trap

import time

async def bad():
    time.sleep(3)             # BLOCKS the whole loop. Nothing else runs!

async def good():
    await asyncio.sleep(3)    # lets other tasks run
# If you must call blocking code, push it to a thread
import asyncio, time

def slow_blocking_job(n: int) -> int:
    time.sleep(2)
    return n * 2

async def main():
    results = await asyncio.gather(
        asyncio.to_thread(slow_blocking_job, 1),
        asyncio.to_thread(slow_blocking_job, 2),
        asyncio.to_thread(slow_blocking_job, 3),
    )
    print(results)            # [2, 4, 6] in about 2 seconds

asyncio.run(main())
Remember: inside async def, never use time.sleep, requests.get, or other blocking calls. For heavy CPU work, use multiprocessing or ProcessPoolExecutor — threads do not help because of Python’s GIL.

# Many requests at once
import asyncio, httpx

URLS = [f"https://httpbin.org/delay/1?id={i}" for i in range(10)]

async def fetch(client: httpx.AsyncClient, url: str) -> int:
    resp = await client.get(url)
    return resp.status_code

async def main():
    async with httpx.AsyncClient(timeout=10) as client:
        codes = await asyncio.gather(*(fetch(client, u) for u in URLS))
    print(codes)            # finishes in ~1-2s, not 10s

asyncio.run(main())
# Error handling
async def safe_get(client: httpx.AsyncClient, url: str) -> dict | None:
    try:
        resp = await client.get(url)
        resp.raise_for_status()
        return resp.json()
    except httpx.TimeoutException:
        print("timed out:", url)
    except httpx.HTTPStatusError as err:
        print("bad status", err.response.status_code, url)
    except httpx.RequestError as err:
        print("network problem:", err)
    return None

# Retry with a delay
async def get_with_retry(client, url, tries: int = 3):
    for attempt in range(1, tries + 1):
        try:
            resp = await client.get(url)
            resp.raise_for_status()
            return resp.json()
        except (httpx.RequestError, httpx.HTTPStatusError):
            if attempt == tries:
                raise
            await asyncio.sleep(2 ** attempt)    # wait 2s, then 4s...

import psycopg2
from contextlib import closing

with closing(psycopg2.connect(DATABASE_URL)) as conn:
    with conn.cursor() as cur:
        try:
            cur.execute("BEGIN")

🧠 Real‑world question: “You have a slow query on a 1M‑row table. How do you approach it?”
Steps: 1) EXPLAIN ANALYZE to see the plan. 2) Check for missing indexes on filter/join columns. 3) Avoid SELECT * — fetch only needed columns. 4) Consider composite indexes if filtering on multiple fields. 5) For heavy analytics, use materialized views or read replicas.
💡 Transaction thinking: always wrap multiple related writes in a transaction. Use SERIALIZABLE only when necessary — it adds overhead. Default READ COMMITTED is fine for most services.

Part 7 — Mini project: Fast URL Checker

This uses almost everything above: typing, dataclass, exceptions, context managers, asyncio, semaphore, and an HTTP client.

# checker.py — run with: python checker.py
import asyncio
import time
from dataclasses import dataclass
from contextlib import contextmanager

import httpx


@dataclass
class Result:
    url: str
    status: int | None
    error: str | None = None

    @property
    def ok(self) -> bool:
        return self.status is not None and self.status < 400


@contextmanager
def timer(label: str):
    start = time.perf_counter()
    try:
        yield
    finally:
        print(f"{label}: {time.perf_counter() - start:.2f}s")


async def check(client: httpx.AsyncClient, sem: asyncio.Semaphore, url: str) -> Result:
    async with sem:
        try:
            resp = await client.get(url)
            return Result(url, resp.status_code)
        except httpx.TimeoutException:
            return Result(url, None, "timeout")
        except httpx.RequestError as err:
            return Result(url, None, type(err).__name__)


async def main(urls: list[str]) -> None:
    sem = asyncio.Semaphore(5)
    async with httpx.AsyncClient(timeout=5, follow_redirects=True) as client:
        results = await asyncio.gather(*(check(client, sem, u) for u in urls))

    for r in results:
        mark = "OK  " if r.ok else "FAIL"
        print(mark, r.url, r.status or r.error)


if __name__ == "__main__":
    urls = [
        "https://www.python.org",
        "https://httpbin.org/status/404",
        "https://httpbin.org/delay/2",
        "https://this-site-does-not-exist-12345.com",
    ]
    with timer("total"):
        asyncio.run(main(urls))
Try this: change the semaphore from 5 to 1 and see the total time grow. Then add retries with asyncio.sleep(2 ** attempt).

Part 9 — Interview‑ready thinking & design logic

🔍 How to answer “design this service” questions
  1. Clarify — what are the inputs, outputs, scale, and edge cases?
  2. Sketch the API — endpoints, request/response models (Pydantic).
  3. Data layer — tables, indexes, transactions. Start simple, then optimise.
  4. Async or sync? — most I/O can be async; CPU‑bound → worker threads/processes.
  5. Error handling — consistent HTTP codes, global exception handlers.
  6. Testing — unit tests with TestClient, integration tests with a test DB.
🧠 “Your endpoint is slow. Walk me through your debugging process.”
Response outline: 1) Check if it’s CPU or I/O bound (logs, metrics). 2) If DB‑heavy, use EXPLAIN and add indexes. 3) If external API, add timeouts and caching. 4) Review async code for accidental blocking calls. 5) Profile with cProfile / py-spy if needed.
🧠 “How would you ensure data consistency when a user places an order?”
Real‑practical: Use a single database transaction: decrement inventory and create the order in the same transaction. If you call an external payment service, use the saga pattern or outbox pattern to avoid distributed transactions. Idempotency keys help with retries.
