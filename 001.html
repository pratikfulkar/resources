Reality check: ₹30–35 LPA is a defensible target, not a guaranteed market entitlement. Your five years are software engineering experience, not five years of dedicated ML/AI experience. Do not market yourself as a senior ML researcher or foundation-model engineer.

Why this range is reasonable

  • 2026 hiring and salary summaries show wide variation by employer type and role. Naukri's published guide gives ₹18–32 LPA for 3–5-year ML engineers, while Instahyre reports stronger product-company and specialist bands. These are directional market references, not guaranteed offers.
  • A 2026 sample of Indian AI job ads found Python, LLMs, agents, RAG and evaluation among frequently requested capabilities. That supports the learning priorities in this plan.
  • Recent agent-engineering role descriptions emphasize production reliability, tool permissions, state, recovery and observability—not just prompt writing.

How to negotiate

  • Ask about the fixed component, variable bonus, joining bonus, equity/ESOPs, benefits and appraisal cycle separately.
  • Compare fixed-to-fixed and total CTC-to-total CTC. Do not accept a headline CTC that is inflated by uncertain variable pay.
  • Do not quote a number before understanding the level, scope and compensation structure where possible.
  • Do not switch only for a small increase if the role has weak engineering ownership or no meaningful AI exposure.

5. Study sequence: learn in dependency order

Avoid studying ten technologies at once. Learn the foundations, then use each topic immediately in a project.

Phase A — Python and service foundationsNov–Dec 2026
  • Python: data structures, typing, modules, exceptions, iterators, context managers.
  • Asyncio, async/await, concurrency basics and HTTP clients.
  • FastAPI: routes, dependency injection, request/response models and background work.
  • Pydantic: validation, settings and structured outputs.
  • PostgreSQL, SQL, transactions, indexes and migrations.
  • Pytest, fixtures, mocking, integration tests and debugging.
  • LLM fundamentals: tokens, context windows, sampling, structured output, tool/function calling, streaming and API errors.
Exit test: Build a tested FastAPI service that calls an LLM, validates structured output, persists results in PostgreSQL and handles timeout/retry failures.
Phase B — Agent architecture and integrationsDec 2026–Jan 2027
  • Agent loop: observe → reason/plan → select tool → execute → verify → continue/stop.
  • LangGraph: state, nodes, edges, conditional routing, checkpointing and persistence.
  • Tool design: schemas, validation, idempotency, timeouts and error handling.
  • MCP: host/client/server concepts, tools, resources, prompts, transports and auth boundaries.
  • Human-in-the-loop approvals, resumability and multi-agent trade-offs.
  • RAG: chunking, embeddings, retrieval, reranking, citations and evaluation.
Exit test: Build a multi-step agent that calls at least three tools, persists state, recovers from a tool failure and asks for approval before a write action.
Phase C — Evaluation, reliability and securityFeb–Mar 2027
  • Offline evaluation datasets and repeatable test runs.
  • Task success, tool-selection accuracy, argument correctness, groundedness, latency and cost.
  • Trajectory-level evaluation, regression testing and failure categorization.
  • LLM-as-judge: calibration, rubrics, human review and limitations.
  • Prompt injection, tool poisoning, data leakage, least privilege and approval gates.
  • Retries, fallbacks, timeouts, rate limits, idempotency and graceful degradation.
Exit test: Run a reproducible evaluation suite and show where the agent fails, why it fails and what changed after improvements.
Phase D — Production deployment and operationsMar–Apr 2027
  • Docker, environment configuration, secrets and deployment basics.
  • AWS fundamentals: compute, storage, IAM, networking and managed databases.
  • OpenTelemetry traces, structured logs, metrics and dashboards.
  • Redis for caching, queues or short-lived state where appropriate.
  • Streaming, concurrency, model routing, token budgets and semantic caching.
  • CI/CD, test automation, service health and operational runbooks.
Exit test: Deploy an agent service with traces, logs, basic metrics, cost/latency reporting and documented failure handling.
Phase E — Interview and job-search executionMay–Jun 2027
  • Polish project demos, architecture diagrams, READMEs and measured results.
  • Prepare system design, Python, backend, SQL and agent architecture interviews.
  • Practice explaining trade-offs, incidents, failures and design decisions.
  • Apply consistently, track interview outcomes and refine weak areas.
  • Negotiate based on role scope, fixed pay and market alternatives.
Exit test: Explain and defend all three projects in a 45-minute technical discussion and complete a practical agent-building exercise.

6. Portfolio: three projects, not ten demos

The portfolio should prove that you can build, evaluate, secure and operate AI systems. Each project should have a working demo or reproducible local setup, tests, architecture diagram and clear technical write-up.

~45% effort

Project 1 — AgentGuard (flagship)

Purpose: An evaluation, observability, reliability and security layer for tool-using AI agents.

  • Record runs, traces and full tool trajectories.
  • Evaluate task completion, tool selection, argument validity and final-answer quality.
  • Track latency, token use, cost, retries and failure reasons.
  • Run regression datasets against prompt, model or code changes.
  • Test prompt injection, malicious tool descriptions and excessive permissions.
  • Show dashboards/reports and compare two versions of an agent.

Proof to publish: Evaluation dataset, baseline results, failure taxonomy, before/after comparison, threat model and demo.

~30% effort

Project 2 — Enterprise Workflow Agent

Purpose: An agent that investigates an engineering or business incident across multiple systems.

  • Connect GitHub, Jira, read-only PostgreSQL, internal docs and code search.
  • Collect evidence, summarize a timeline, identify likely causes and produce a report with citations.
  • Use MCP or well-defined tool adapters for integrations.
  • Require human approval before creating tickets, changing records or performing other write actions.
  • Handle missing data, tool timeouts, conflicting evidence and retries.
  • Send its traces and evaluation results into AgentGuard.

Proof to publish: End-to-end demo, tool schemas, permission model, sample incident report and failure/recovery walkthrough.

~25% effort

Project 3 — CodeShift / Behavioral Verification Engine

Purpose: Strengthen the existing AI-assisted code migration testing work.

  • Compare old and migrated implementations with differential execution.
  • Use property-based, metamorphic and stateful tests.
  • Check API contracts, database side effects and error behavior.
  • Record migration attempts and classify behavioral drift.
  • Report coverage, regressions and reproducible failing cases.

Starting asset: Existing Behavioral Verification Engine and its prior 40+ migration attempts. Verify the dataset, metrics and claims before publishing them.

Existing work to consolidate

  • Agent Trajectory Evaluation Platform: fold its strongest trajectory capture/evaluation capabilities into AgentGuard.
  • MCP Tool-Poisoning Scanner: integrate its threat checks into AgentGuard rather than leaving it as an isolated toy project.
  • Behavioral Verification Engine: evolve it into CodeShift rather than restarting from scratch.
Do not invent metrics. Publish accuracy, time saved, reliability or test counts only when you can explain the measurement method, sample size, baseline and limitations.

7. Weekly study and execution routine

Target around 3.5 focused hours on most workdays. Keep one lighter/rest day. Consistency and project output matter more than long study sessions.

Test & debug30 minWrite tests, reproduce failures, inspect logs and improve reliability.
Career preparation30 minResume/LinkedIn, system design, interview practice or job research.
Buffer20 minReview progress, update the task list and plan tomorrow.

Suggested weekly rhythm

  • Monday–Thursday: learning + implementation + tests.
  • Friday: integration, refactoring, documentation and demo recording.
  • Saturday: longer project session, mock interview or system design practice.
  • Sunday: rest or a short weekly review only.

Use a single active learning topic and a single primary project at a time. Avoid switching frameworks because a new tool is trending.

13. Rules to stay focused

  1. Build more than you watch. Keep passive learning to a small part of each session.
  2. One main project at a time. Integrate smaller ideas into the three portfolio projects.
  3. Understand fundamentals before framework hopping. Agent state, control flow, tools, evaluation and safety matter more than framework count.
  4. Do not fake seniority. Present yourself as an experienced software engineer developing deep Applied AI specialization.
  5. Measure outcomes honestly. Every metric needs a baseline, method and reproducible evidence.
  6. Protect your current job performance. Do not sacrifice income or reliability for an unrealistic study schedule.
  7. Review every Sunday. What did you ship? What did you learn? What is blocked? What is next?
  8. Do not endlessly reorder LinkedIn skills. Update the profile when your demonstrated ability changes, not every few days.
North-star outcome by June 2027: Be able to design, build, evaluate, secure and deploy a real tool-using AI system; explain the architecture and trade-offs; show evidence in three focused projects; and interview as a senior software engineer specializing in Applied AI systems.
